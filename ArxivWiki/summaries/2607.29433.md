# Know It, Act on It: Investigating Memory Utilization in LLM Personalization

arXiv: [2607.29433](https://arxiv.org/pdf/2607.29433v1) &middot; Published 2026-07-31 &middot; Recommendation: **Priority review** (score 20/25)

_Pre-extraction: this paper has only been screened on its abstract, not read in full yet._

## Key Highlights

- Agents routinely pass the recall test and fail the paired behavioural test on the same preference.
- The information was fully present in context -- this is not a retrieval failure that a better memory system fixes.
- Better memory architectures narrow the gap but do not close it.
- Utilisation is weakest for health and therapy-related preferences, which is exactly where failing to act carries the highest real-world cost.

## Why It Matters for Enterprise AI

Most teams evaluating agent memory are measuring the wrong thing. A recall benchmark can look healthy while the agent routinely ignores what it recalled, and the standard remedy -- buy or build a better memory layer -- does not address it, because the information was already there. The practical consequence is that memory evaluation needs a behavioural half: put the agent in a situation where the stored preference should change what it does, and check whether it does. The concentration of failures in health and therapy contexts also means the risk is not evenly distributed; the cases where an ignored preference does real harm are the cases the agent handles worst.

## Business Applications

- Add a behavioural half to your agent memory evaluation -- test whether a stored preference actually changes the response, not just whether the agent can repeat it.
- Stop treating persistent memory failures as a retrieval problem to be solved by procurement; measure the Know/Act split before buying a memory layer.
- Prioritise utilisation testing on the highest-consequence preference categories in your domain, since the gap is not uniform.
- Require memory vendors to report utilisation, not just recall, as an acceptance criterion.

## Why triage flagged this

Memory is a priority topic and this separates two failures everyone currently conflates. Paired Know and Act tests on the same preference show agents routinely pass recall and fail the behavioural scenario -- so buying a better memory architecture does not fix it, because the information was already there. Scale supports the claim rather than gesturing at it: 16 systems, 5 memory architectures, 1,000 preferences at three expression strengths. The finding that utilisation is weakest exactly where failure costs most (health, therapy) is the executive line, and it needs no ML vocabulary at all. Enterprise readiness held at 3 -- it is a measurement, not a fix -- but the measurement is directly runnable against your own agents, which is more than most evaluation papers offer.
