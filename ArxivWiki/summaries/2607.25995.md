# Does Runtime Topology Context Improve LLM-Generated Kubernetes Security Patches?

arXiv: [2607.25995](https://arxiv.org/pdf/2607.25995v1) &middot; Published 2026-07-28 &middot; Recommendation: **Archive** (score 14/25)

_Pre-extraction: this paper has only been screened on its abstract, not read in full yet._

## High-Level Summary

Measures whether LLMs can safely auto-fix Kubernetes security findings. Given each finding in isolation, patch correctness on topology-dependent issues was 11.1%. Feeding the model the live service call graph and service-account bindings first raised it to 78.0%, and a control group confirms the gain comes from the topology data rather than from a longer prompt.

## Key Highlights

- A patch that satisfies the scanner can still sever a live service dependency the model could not see, crashing downstream callers -- a compliant fix with a destructive blast radius.
- 248 trials over a purpose-built 36-deployment healthcare cluster with 31 injectable findings across seven dependency classes, each labelled for topology dependence against cluster ground truth.
- The effect holds for every model tested and six of seven dependency classes, from credential and network-policy issues down to RBAC, where the gain is smaller.
- A topology-independent control shows no effect at all, which rules out generic prompt enrichment as the explanation.

## Why It Matters for Enterprise AI

This is the difference between an auto-remediation pilot that gets shut off after its first outage and one that stays on. The finding is architectural, not model-dependent: what you feed the model matters more than which model you pick, so the work is in building the context pipeline (call graph, service-account bindings) rather than waiting for a better model. It also gives a defensible answer to the security-versus-availability objection that usually blocks these projects, and a way to triage which findings are safe to auto-patch today.

## Business Applications

- Condition any LLM-based remediation tooling on live service-mesh call edges and service-account bindings before it proposes a patch, instead of prompting per scanner finding.
- Classify KSPM findings by topology dependence and let the agent auto-patch only the topology-independent ones until the context pipeline exists.
- Use the dependency-class breakdown to set human-approval thresholds -- RBAC changes retain a reviewer, credential and network-policy fixes can move faster.
