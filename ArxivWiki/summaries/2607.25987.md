# \textsc{IH-Benchmark}: A Conflict-Centered Benchmark for Instruction-Hierarchy Robustness in LLM Applications

arXiv: [2607.25987](https://arxiv.org/pdf/2607.25987v1) &middot; Published 2026-07-28 &middot; Recommendation: **Archive** (score 15/25)

_Pre-extraction: this paper has only been screened on its abstract, not read in full yet._

## High-Level Summary

Tests what a model actually does when its system prompt, its user, and a tool's output tell it different things. Across 37 models, obedience to the system prompt ranged from 98.2% to 20.5% -- and critically, the models that held firm against a pushy user often folded when the same conflicting instruction arrived inside a tool result instead.

## Key Highlights

- System-prompt-versus-user compliance does not predict system-prompt-versus-tool-output compliance. Passing the first tells you nothing about the second, so vendor claims based on the first are not evidence of injection resistance.
- Tested over 44 constraint families across finance, health, retail, coding and generic settings, with a binary pass/fail protocol rather than a graded score.
- Hardening the system prompt with stronger warnings fixed some models' failures and did nothing for others at any strictness level -- prompt hardening is not a general mitigation.
- The failures that survive are the quiet ones: models refused unauthorized purchases and bulk ticket closure fairly reliably, but accepted injected disclaimers and small factual distortions.

## Why It Matters for Enterprise AI

Any agent that reads a tool result, a retrieved document, an API response, or another agent's output has the U>T surface this paper measures, and most teams have only ever tested the S>U surface. This changes what you require in an agent security review: hierarchy compliance has to be measured per conflict surface, and a model approved for a chat product cannot be assumed safe for a tool-calling deployment without re-testing. It also means the mitigation you probably reached for first -- a sterner system prompt -- provably does not work on some models.

## Business Applications

- Add a tool-output injection conflict suite to model qualification, separate from the system-prompt tests already in use, and make it a gate before an agent gets write-capable tools.
- Re-test any model already approved for chat use before promoting it into an agentic workflow, since the two surfaces do not correlate.
- Stop treating prompt hardening as the mitigation of record; classify models by whether hardening actually moves them and constrain tool permissions for those it does not.

## Why triage flagged this

The single most decision-relevant paper of the batch for anyone deploying tool-using agents. It shows that instruction-hierarchy robustness is not one capability: strong system-over-user compliance does not predict resistance when the conflicting instruction arrives through a tool result, which is precisely the enterprise prompt-injection surface. Evidence is broad and specific -- 37 models, compliance spanning 98.2% to 20.5%, 44 constraint families across finance, health, retail and coding. The finding that subtle failures (injected disclaimers, small factual distortions) survive where dramatic ones are refused is both counterintuitive and immediately quotable to a risk owner.
