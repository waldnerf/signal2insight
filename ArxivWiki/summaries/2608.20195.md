# From Agent Behaviour to Agent-Friendly Documentation: An Empirical Study of How Coding Agents Discover, Read, and Write Technical Documentation

arXiv: [2608.20195](https://arxiv.org/pdf/2608.20195v1) &middot; Published 2026-08-20 &middot; Recommendation: **Review fully** (score 20/25)

_Pre-extraction: this paper has only been screened on its abstract, not read in full yet._

## High-Level Summary

Technical documentation has always been written for human developers, but coding agents now author a growing share of code changes -- and this is the first empirical study of which documents agents actually consult. Across 557 real agentic coding sessions and 33,097 agentic pull requests, the findings challenge current documentation practice directly.

## Key Highlights

- Agent-facing artifacts (instruction files, working notes) account for 60.5% of documentation interactions, versus only 10.6% for classical technical docs and 1.3% for API references.
- Large real-world dataset (94,813 development events, 690,260 file-level change records), not a synthetic or small-sample study.
- Directly implies most engineering orgs are still investing documentation effort where agents least look.

## Why It Matters for Enterprise AI

Any engineering org adopting coding agents is currently maintaining documentation optimized for human readers, while this study shows agents overwhelmingly consult a different category of artifact -- a concrete, evidence-backed reason to change documentation investment now, not later.

## Business Applications

- Reallocate documentation effort toward agent-facing instruction files and working notes based on the measured 60.5%/10.6%/1.3% split.
- Audit whether existing API references and classical docs are actually being read by the coding agents in use.
- Use the findings to set a documentation strategy for an agent-majority contributor base before investing further in classical docs.
