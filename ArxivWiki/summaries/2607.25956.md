# Large Language Model for Operations Research Formulation Selection in Multi-Warehouse Inventory Allocation

arXiv: [2607.25956](https://arxiv.org/pdf/2607.25956v1) &middot; Published 2026-07-28 &middot; Recommendation: **Priority review** (score 20/25)

_Pre-extraction: this paper has only been screened on its abstract, not read in full yet._

## High-Level Summary

At JD.com, warehouse allocation is solved by mixed-integer programming, but no single formulation is best for every situation. Rather than asking an LLM to do the optimisation, they trained it to pick which of several solver-ready formulations to run per instance. Formulation-choice accuracy went from 21.45% to 50.42% at top-1, and realised allocation quality beat both the incumbent and the best fixed formulation by 12.57 points.

## Key Highlights

- The LLM never does the maths -- it routes each instance to one of a library of expert formulations, each encoding a different allocation priority, and a real solver executes it.
- Training signal comes from the solver itself: measured allocation-quality gaps between formulations become preferences, so the model is rewarded against realised outcomes rather than a human-labelled answer key.
- Better routing accuracy translated into better realised allocation quality, not just a better match to the label -- the two are reported separately.
- Evaluated on real instances from one of China's largest e-retailers, with the remaining gap to a perfect hindsight oracle stated at 4.85 points.

## Why It Matters for Enterprise AI

Most enterprises already own working operations-research models, and the usual AI pitch is to replace them. This does the opposite and beats the incumbent: keep the solvers, and use the LLM for the judgment call nobody had automated -- which model fits this situation. That is a far cheaper and more auditable integration than replacing a certified optimisation stack, because the solver still produces the answer and remains inspectable. The pattern transfers to any domain with several valid models and no universally best one: pricing, routing, scheduling, capacity planning.

## Business Applications

- Put an LLM router in front of an existing solver library to select formulations per instance, instead of replacing the optimisation stack.
- Train the router against solver-measured outcome gaps rather than human labels, which removes the annotation bottleneck for this class of problem.
- Report an ex-post oracle gap alongside accuracy so the remaining headroom in a routing system is visible to the business rather than implied.
